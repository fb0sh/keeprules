# KEEPTIDY — 工程卫生与资源管理规范

适用于当前项目内的 Coding Agent 及其委派的 Subagent。

**核心原则：只管理当前项目授权范围内的资源；可控的临时工作集中在项目 `./tmp/`；保护用户现场；任务完成后清理自身资源。**

本规则中的 **MUST** 表示必须执行，**MUST NOT** 表示禁止执行，**SHOULD** 表示默认执行、存在合理原因时可调整。

## 1. 工作范围与项目根目录

- **MUST** 在操作前明确当前项目根目录（下称 `PROJECT_ROOT`）以及任务授权范围。Git 项目优先以对应工作区根目录为准；其他项目依据用户指定的项目根目录。
- **MUST** 保护用户已有文件、未提交修改、运行中的服务与其他任务资源。
- **MUST NOT** 擅自操作其他仓库、用户主目录配置、系统目录或任务范围外的文件。
- **MUST** 在写入、移动和删除文件之前确认其真实目标路径处于授权范围内；对符号链接及路径穿越保持警惕。
- **MUST NOT** 借助符号链接对授权范围外的资源进行写入、修改或清理；读取工具链和项目依赖所需的外部只读文件时，遵循项目现有约定及授权边界。
- 项目本身位于系统 `/tmp/` 时，**MUST** 停止与该路径冲突的操作并说明原因。

## 2. 项目临时目录：唯一可控工作区

### 2.1 系统 `/tmp/` 边界

- **MUST NOT** 主动读取、列举、写入、修改、清理或删除系统 `/tmp/` 及其内容。
- **MUST NOT** 主动把系统 `/tmp/` 作为编译、测试、下载、调试、日志、缓存、脚本或数据库的工作目录。
- **MUST NOT** 使用符号链接或其他路径绕过上述限制。
- 对 Agent 可控制的工具与子进程，**MUST** 在启动前配置项目级临时目录。
- 对确实无法重定向、且会主动要求 Agent 操作系统 `/tmp/` 的步骤，**MUST** 跳过该步骤并报告阻塞；**MUST NOT** 尝试在系统 `/tmp/` 中事后清理。
- 本规则约束 Agent 主动执行及能够配置的文件系统操作；操作系统和已有服务内部不可控的行为，应记录限制并避免作出未经验证的合规承诺。

### 2.2 项目内目录布局

可控的临时文件和中间结果统一放在 `PROJECT_ROOT/tmp/`。按需使用以下结构：

```text
project/
└── tmp/
    ├── runs/
    │   └── <task-id>/
    │       ├── scratch/    # 临时脚本、临时数据库、测试中间文件
    │       ├── logs/       # 脱敏诊断日志
    │       ├── outputs/    # 待复核或待转交结果
    │       ├── backups/    # 当前任务的短期恢复副本
    │       └── state/      # 任务状态与资源归属信息
    ├── s/
    │   └── <task-id>/     # Unix Socket 等需要短路径的临时资源
    └── cache/             # 可以安全复用的项目级缓存
```

- **MUST** 在需要时创建对应目录；小任务可以只创建 `tmp/runs/<task-id>/scratch/`。
- **MUST** 为并行任务分配唯一的 `task-id`，优先使用 6–12 位短标识，并在创建时检查碰撞；Subagent 可使用同一任务下独立子目录或独立任务 ID。
- **MUST** 确保 Git 项目根目录的 `.gitignore` 正确忽略 `/tmp/`，保留已有忽略规则；必要时用 Git 的实际匹配结果检查。
- **MUST NOT** 因忽略规则而假设已有跟踪文件自动退出版本控制；发现已跟踪的临时文件时报告并等待适当授权。
- **MUST** 对现存 `tmp/` 内容采取保守态度，确认归属前保留。
- **SHOULD** 复用项目已有且合理的正式构建目录（例如 Rust `target/`），避免无意义地迁移增量编译产物。

### 2.3 临时目录环境变量

对 Agent 启动的可控编译、测试、开发、下载和调试子进程，**MUST** 在启动前创建临时目录，并按平台及工具支持设置：

```bash
TASK_TMP="$PROJECT_ROOT/tmp/runs/$TASK_ID/scratch"
mkdir -p "$TASK_TMP"
TMPDIR="$TASK_TMP" TMP="$TASK_TMP" TEMP="$TASK_TMP" <command>
```

- `PROJECT_ROOT`、`TASK_ID` 和 `<command>` 为示意占位值，执行时应替换为已确认的实际值；使用**绝对路径**传递临时目录。
- **MUST** 仅对当前任务及其子进程注入设置；**MUST NOT** 为此修改用户全局 shell 配置或其他项目环境。
- **SHOULD** 根据工具能力设置专用缓存、下载与构建参数；不得假定 `TMPDIR` 可以控制所有产物路径。
- **MUST** 尊重项目既有构建目录和缓存策略，只在确有必要时调整。
- 在 Windows 上使用相应的进程级环境变量和本机路径 API；同样只管理项目 `tmp/`。

### 2.4 Unix Socket 与短路径

- Linux/macOS 上需要创建 pathname Unix Socket 时，**MUST** 在绑定前检查完整**绝对路径的字节长度**及平台限制。
- **SHOULD** 优先缩短测试名称、任务标识和 Socket 文件名；路径空间不足时使用 `PROJECT_ROOT/tmp/s/<task-id>/`。
- **MUST NOT** 为规避路径限制把 Socket 转移到系统 `/tmp/`，或通过仓库外部符号链接逃逸。
- 当项目根目录本身过长、项目内短路径依然无法满足限制时，**MUST** 说明受限步骤，并在当前授权范围内选择兼容方案。

## 3. 文件修改、检查点与 Git 安全

- **MUST** 在修改前检查相关文件和当前 Git 状态；在提交前检查最终差异与状态。
- **MUST** 保护用户及其他 Agent 的未提交修改；**MUST NOT** 为解决冲突而覆盖他人的工作。
- **MUST NOT** 未经授权执行 `git reset --hard`、`git clean -fdx`、强制推送、历史重写、删除分支或自动提交。
- **MUST NOT** 将临时文件、真实凭证、日志和无关构建产物加入版本控制。
- 对批量删除、大规模重构、重要依赖升级、数据迁移等高影响变更，**MUST** 先建立与风险相匹配的恢复检查点，并记录恢复方式与位置。
- **MUST NOT** 擅自 `git stash` 用户工作区或创建会干扰现有工作流的提交；优先使用独立分支、受控文件副本或项目既有的安全备份方式。
- `tmp/runs/<task-id>/backups/` 只适合短期恢复。若恢复能力在任务结束后仍然必需，**MUST** 将备份转入项目认可的持久化位置并明确保留期限。
- 生产环境、真实业务数据或不可逆操作的授权由 `KEEPSECURED.md` 约束。

## 4. 进程、容器与并发资源

- **MUST** 记录本任务启动的后台进程、用途和生命周期；需要清理时，结合启动时间、任务标识或容器标签确认归属，避免仅凭 PID 误杀。
- **MUST** 优先复用适用的已有服务，控制并行编译、测试和 Subagent 数量。
- **MUST** 为长时间运行的操作设置适当超时、取消或状态检查手段。
- **MUST** 在任务完成时停止本任务启动且无需保留的进程、容器及相关资源。
- **MUST NOT** 终止用户、系统、其他任务或其他 Agent 的资源。
- **MUST NOT** 未经授权运行全局 Docker 清理、全局缓存清理或影响无关资源的批量命令。
- **SHOULD** 使用独立任务目录、进程组、容器名或标签进行归属识别。

## 5. 磁盘、缓存、日志及文件监听

- **MUST** 关注单任务和项目 `tmp/` 的总占用、文件数量、剩余磁盘空间及异常增长。
- **MUST** 避免无限增长的日志、缓存、下载文件和重试产物；对大输出进行限制或安全截断。
- **MUST** 在空间不足或超出明确预算时暂停新增消耗，先诊断本任务产生的资源。
- **SHOULD** 将单任务临时文件 2 GiB、并行 Subagent 4 个作为初始软参考值；任务规模或用户授权可调整，阈值本身**不授予删除权限**。
- **SHOULD** 保留有效共享缓存，避免反复下载和编译；按工具能力把可控的项目级缓存放入 `tmp/cache/`。
- **SHOULD** 根据项目实际扫描范围，排除 `tmp/` 参与无关的 IDE 索引、开发服务器监听、打包、备份和递归测试发现。
- **MUST NOT** 为排除临时目录而擅自大范围修改构建配置；只进行必要且可验证的项目级调整。

## 6. 错误处理与安全重试

- **MUST** 检查失败的退出状态与关键错误信息，区分代码、环境、权限、网络和外部服务问题。
- **MUST** 对确定性错误优先修复根因；对瞬态错误采用有限重试及适当退避。
- **MUST** 在相同条件下连续失败两次后改变排查策略；达到预设尝试上限仍无法解决时，报告阻塞。
- **MUST** 在重试有副作用的操作前检查已有状态，避免重复写入、重复迁移或重复启动资源。
- **MUST NOT** 通过跳过安全检查、隐藏失败或伪造结果宣称成功。
- **SHOULD** 继续推进与阻塞项独立的已授权工作。

## 7. 临时资源生命周期与回收

临时资源分为三类：

| 类别 | 典型位置 | 处理原则 |
| --- | --- | --- |
| 即时临时资源 | `runs/<id>/scratch/`、`s/<id>/` | 任务成功结束且确认无依赖后清理 |
| 待复核资料 | `runs/<id>/logs/`、`outputs/`、`backups/` | 完成复核、交付或迁移后按保留策略清理 |
| 跨任务共享缓存 | `cache/` | 按归属、有效性和资源预算清理 |

- **MUST** 仅清理可确认属于当前任务、真实路径位于项目 `tmp/` 内、且不再被使用的资源。
- **MUST** 在正常完成时清理无用 scratch 和短路径资源；将必要的交付物、测试证据及长期恢复资料转入项目认可的位置。
- **MUST** 对异常中断或归属不明的任务目录保留现场；恢复后先确认任务状态与资源所有权。
- **MUST NOT** 跟随符号链接递归删除，或使用无明确目标边界的清理命令。
- **MUST NOT** 触碰系统 `/tmp/`、其他任务资源或全局缓存。
- **SHOULD** 对已结束任务的诊断日志采用默认 7 天的复查期，过期仅表示“可评估清理”，并不等于允许直接删除。
- 历史目录回收**SHOULD** 先列出候选项（dry-run），确认归属、任务结束、无活跃引用、无保留标记和删除边界，再执行实际删除。
- **MUST NOT** 仅凭任务编号先后、目录年龄或磁盘阈值自动清理未知内容。
- 对外部工具、操作系统或用户创建的资源，遵守其原有所有权与生命周期。

## 8. Subagent 协作

- **MUST** 在委派任务时向 Subagent 注入适用规则、项目根目录、授权范围及临时目录约定。
- **MUST** 为并行任务划分清晰的文件与资源边界，避免相互覆盖。
- **MUST** 在合并结果前检查冲突、修改范围和验证结果。
- **MUST NOT** 无界递归委派或无限增加并发。
- 无需增加额外的强制证明、握手或专门的 Subagent 规则执行框架。

## 9. 验证与交付

完成任务前，**MUST** 核对：

- [ ] 变更范围符合用户任务，已有文件和未提交修改得到保护。
- [ ] 可控临时产物在项目 `tmp/` 内，系统 `/tmp/` 未被主动访问或清理。
- [ ] Git 项目的 `/tmp/` 忽略规则生效，Git 状态与最终差异已检查。
- [ ] 必要的检查、测试和实际结果已经如实记录。
- [ ] 本任务后台资源已处理，短期临时资源已安全清理或说明保留原因。
- [ ] 关键备份、证据和交付物已有明确的长期保留位置或后续处置方式。
- [ ] 遗留问题、环境限制及未完成验证已说明。

最终说明简洁覆盖：**完成的变更、验证结果、遗留风险、资源清理状态**；仅在适用时附加检查点位置。

## 10. 规则适用与冲突

- 系统、平台及其他更高优先级约束始终适用；用户授权定义任务范围，规则本身不扩大权限。
- 安全与敏感信息的专门要求遵循 `KEEPSECURED.md`；实现取舍与改动复杂度遵循 `KEEPLEAN.md`。
- 当具体工具限制与本规则发生冲突时，**MUST** 优先采取安全、可逆、局部的处理方式；仍无法处理则报告阻塞。
